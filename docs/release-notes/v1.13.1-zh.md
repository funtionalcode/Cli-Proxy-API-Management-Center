## Overview

v1.13.1 是一个以凭证操作性能、请求诊断和升级兼容性为重点的维护版本。针对大规模凭证池，单凭证刷新、启停、字段修改和配置编辑保存现在尽量使用定向查询与局部对账，减少不必要的全量凭证列表读取，同时继续保留多凭证操作和初始列表加载所需的完整集合语义。

Request Monitoring 现在可以区分请求模型、CPA 路由模型和上游响应模型；当响应模型与路由模型不一致时，会以琥珀色提示实际响应模型，便于识别上游模型切换或降级。新版 CPA Usage queue 提供的 session、parent session、generate、stream 等请求元数据也会进入持久化与监控链路；旧数据或未提供这些字段的 CPA 会自然降级，不影响既有用量记录。

本版本还修复了历史 SQLite 数据中模型价格 configured 标记以 REAL 数值保存时导致价格加载失败的问题，以及 OAuth 排除模型接口显式返回 null wrapper 时被错误回退到其他字段的问题。

## Highlights

### Features

- Request Monitoring 的模型列现在区分请求模型、路由模型和上游响应模型；当响应模型与路由模型不一致时，以琥珀色响应模型与“模型不一致”标记提示异常路由结果。（Web / Manager Server）
- 接入 CPA Usage queue 的 `response_model`、`session_id`、`parent_session_id`、`access_token_sha256`、`generate` 和 `stream` 字段，并贯通 SQLite、Monitoring API、JSONL 导出和兼容用量导入/导出链路；显式 `false` 与缺失值保持可区分。（Manager Server / Web）

### Performance

- 单凭证刷新改为按物理文件名、运行时 ID 和 auth index 做定向查询与局部对账，避免每次轮询都重新拉取完整凭证集合；旧 CPA 不支持定向参数时仍可安全回退。（Web / CPA）
- 单凭证启停、优先级、备注、WebSocket 等字段修改，以及配置编辑器保存后的对账改为局部 source reconciliation；多凭证操作继续使用完整列表以维持碰撞检查和批处理安全语义。（Web）

### Fixes

- 修复 OAuth 排除模型接口显式返回 `null` wrapper 时继续回退读取 `items` 或 provider 顶层字段的问题，避免把本应为空的排除模型列表恢复成旧值。（Web）
- 修复历史 SQLite `model_prices` 及价格 tier 表中的 `*_configured` 标记以 REAL 数值保存时，Manager Server 因按整数扫描而导致模型价格、Dashboard 或 Usage Analytics 加载失败的问题；数值 0 仍视为 false，非零有限数值视为 true，非法存储类型继续失败关闭。（Manager Server）

### Docs

- 更新 README 凭证管理相关截图，使文档与当前界面保持一致。

## Upgrade Notes

- **本版本会自动为 `usage_events` 增加 6 个可空字段：`response_model`、`session_id`、`parent_session_id`、`access_token_sha256`、`generate`、`stream`。** 迁移为在线增列，不需要手动数据库操作或离线维护，历史记录保持原样。
- **CPA 最低兼容基线仍为 v7.3.2。** 新增请求元数据只有在 CPA 实际提供对应 Usage queue 字段时才会出现；较旧或不提供这些字段的 CPA 仍可继续使用，只是相关诊断信息为空。
- 本版本优化的是单凭证操作中的不必要全量读取；Accounts 初次进入时仍需要完整凭证集合，以维持全局搜索、筛选、排序、统计和选择语义。
- 历史模型价格 configured 标记兼容修复只改变读取方式，不会重写或清洗已有价格数据。
