## Overview

v1.13.1 is a maintenance release focused on credential-operation performance, request diagnostics, and upgrade compatibility. For large credential pools, single-credential refreshes, status changes, field updates, and configuration-editor saves now prefer targeted lookups and local reconciliation instead of unnecessary full auth-file inventory reads, while multi-credential operations and initial list loading retain complete-set semantics where correctness requires them.

Request Monitoring can now distinguish the requested model, CPA-routed model, and upstream response model. When the response model differs from the routed model, the actual response model is highlighted in amber to make upstream model switching or downgrades visible. Request metadata emitted by newer CPA Usage queues, including session hierarchy and generate/stream flags, is also preserved through persistence and monitoring. Older events or CPA versions that do not emit these fields degrade cleanly.

This release also fixes model-price loading when legacy SQLite databases contain REAL values in configured-flag columns, and fixes OAuth excluded-model handling when the API explicitly returns a null wrapper.

## Highlights

### Features

- Distinguish requested, routed, and upstream response models in Request Monitoring. A response model that differs from the routed model is shown with an amber response line and “Model mismatch” badge. (Web / Manager Server)
- Preserve CPA Usage queue fields `response_model`, `session_id`, `parent_session_id`, `access_token_sha256`, `generate`, and `stream` across SQLite persistence, Monitoring APIs, JSONL export, and compatible usage import/export. Explicit `false` remains distinct from an absent value. (Manager Server / Web)

### Performance

- Scope single-credential refresh polling to targeted lookups by physical file name, runtime ID, and auth index instead of repeatedly loading the complete credential inventory. Older CPA versions that ignore targeted query parameters still fall back safely. (Web / CPA)
- Scope single-credential status changes, priority/note/WebSocket field edits, and configuration-editor save reconciliation to the affected source. Multi-credential operations retain full-list checks for collision and batch-safety semantics. (Web)

### Fixes

- Fix OAuth excluded-model responses with an explicit `null` wrapper incorrectly falling through to `items` or provider-level keys, which could restore values that should remain empty. (Web)
- Fix model-price, Dashboard, and Usage Analytics loading failures when legacy SQLite `model_prices` or pricing-tier `*_configured` flags are stored as REAL values. Numeric zero remains false, finite non-zero numeric values are treated as true, and invalid storage types still fail closed. (Manager Server)

## Upgrade Notes

- **This release automatically adds six nullable columns to `usage_events`: `response_model`, `session_id`, `parent_session_id`, `access_token_sha256`, `generate`, and `stream`.** The schema expansion is online and requires no manual database action or offline maintenance; existing historical rows remain unchanged.
- **The minimum CPA compatibility baseline remains v7.3.2.** The new request metadata appears only when CPA actually emits the corresponding Usage queue fields. Older or non-emitting CPA versions continue to work with those diagnostics left empty.
- This release reduces unnecessary full-inventory reads for single-credential operations. Initial Accounts loading still requires the complete credential set to preserve global search, filtering, sorting, metrics, and selection semantics.
- The legacy configured-flag compatibility fix changes read behavior only; it does not rewrite or clean existing model-price data.
