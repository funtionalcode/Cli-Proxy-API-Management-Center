## Overview

v1.12.13 is a maintenance release focused on reliability, correctness, and data safety. The Accounts experience fixes observed xAI weekly quota presentation and prefixed model exclusions while adding Codex plan-remaining sorting. Manager Server now preserves manual model prices during sync, hardens credential handling at the UsageEvent persistence boundary, and keeps legacy Usage JSONL imports compatible.

This release does not introduce a database schema migration, does not scan or rewrite historical `usage_events` during startup or upgrade, and does not require offline maintenance.

## Highlights

### Features

- Add **Plan remaining** sorting to Accounts. Paid Codex accounts can be ordered by expiry time while Free and unknown plans remain after valid paid plans; the default sort behavior is unchanged. (Web)

### Fixes

- Show observed xAI weekly credits and product usage when upstream reports them even if `planType` is unconfirmed. Billing limits and PAYG remain gated behind confirmed paid plans, and unconfirmed quota telemetry does not affect account health or automatic disable recommendations. (Web)
- One-click model-price sync no longer overwrites rows saved with `source: "manual"`. Manual prices remain authoritative until the user deletes or replaces them. (Manager Server)
- Fix model exclusions for credentials using a Prefix. Runtime model IDs are mapped back to the canonical CPA exclusion rule IDs so exclusions actually take effect; unresolved mappings fail closed and surface a warning. (Web)
- Restore import compatibility for Usage JSONL exported by older versions. Historical noncanonical `event_hash` values are deterministically canonicalized when imported into a clean database, while upgraded databases continue to deduplicate against existing legacy identities without creating duplicate events. (Manager Server)

### Security

- Add a unified sensitive-field sanitization boundary before UsageEvent persistence to SQLite, covering known API keys, Bearer / Authorization values, cookies, session tokens, private keys, and related credential forms while retaining useful diagnostic context. (Manager Server)
- Normalize or pseudonymize newly persisted opaque hash/source identities. Normal collector/runtime persistence continues to require canonical event identities; legacy compatibility is limited to the Import boundary. (Manager Server)

## Upgrade Notes

- **No database schema migration or offline maintenance is required.** Upgrade startup does not scan or rewrite existing `usage_events`.
- UsageEvent credential sanitization applies to **new writes after upgrading**. Existing `usage.sqlite` files, old backups, and previous exports are not rewritten automatically. If historical data may have contained live credentials, rotate those credentials; historical-file cleanup is not a substitute for rotation.
- No new required configuration is introduced; existing Manager Server and CPA-hosted / external-panel deployment modes remain unchanged.
- Usage JSONL exported by older versions can be imported directly without preprocessing or offline conversion.
