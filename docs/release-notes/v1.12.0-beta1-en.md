## Overview

This is the first beta of v1.12.0, focused on a unified credential workspace, provider quota evidence, and account-level diagnostics. The frontend consolidates credentials, quotas, configuration, models, health, and request activity under `/accounts`. Manager Server adds persisted quota-window lifecycles and identity-scoped monitoring readers while preserving explicit capability boundaries between CPA Panel and Full Docker deployments.

## Highlights

### Features

- Make `/accounts` the unified credential-management entry, retain compatibility redirects from `/auth-files` and `/quota`, and provide responsive table and card views (`web/accounts`).
- Combine overview, quota, configuration, models, activity, and diagnostics in credential details, including health, recent requests, reauthorization, and recovery guidance (`web/accounts`).
- Present complete and previous provider cycles, model scopes, reset records, precise observation times, usage forecasts, and quota comparisons (`web/quota`).
- Make provider quota refresh explicit and separate from history refresh, serialize repeated refreshes by provider, and preserve existing quota when refreshes fail (`web/quota`).
- Persist allowlisted quota observations, windows, activations, cycles, and snapshots in Manager Server without storing raw provider response bodies (`manager-server/quota`).
- Query account history and window usage by credential identity, provider, and exact time bounds, with recent-request status and credential drilldowns (`manager-server/monitoring`).
- Preview and manage OAuth excluded models and model aliases in the unified workspace, with rollback for failed multi-provider alias mutations (`web/auth-files`).
- Present account-scoped status, proxy, excluded-model, and OAuth configuration in the credential configuration workspace (`web/accounts`).

### Fixes

- Scope identities by file name, `auth_index`, provider, and source to prevent attribution errors across duplicate credentials, providerless records, and caches (`web/identity`, `manager-server/identity`).
- Clear stale quota, inspection, and OAuth state before layout commits when the CPA connection or Manager scope changes, and ignore late responses from the previous scope (`web/connection-scope`).
- Pin multi-step credential mutations to the CPA connection captured at operation start so stale 401 responses or metadata cannot affect the active session (`web/api`).
- Evaluate Manager storage, request monitoring, and server inspection separately across Full Docker and CPA Panel modes instead of reusing stale capability results (`web/panel-mode`).
- Normalize provider reset timestamps, cycle boundaries, and quota availability while retaining prior results after failed refreshes or empty-window responses (`web/quota`).
- Keep credential editor previews and confirmation messages redacted instead of exposing raw authentication content (`web/auth-files`).

### Performance

- Route account-window usage through covered derived monitoring readers, with raw `usage_events` fallback for uncovered edges and tails (`manager-server/monitoring`).
- Add credential-window and recent-request indexes to reduce scans for account history, window usage, and latest status lookups (`manager-server/sqlite`).

### Refactor

- Reuse the detail drawer, health badges, quota-window cards, relative-time presentation, and shared data colors across the Accounts workspace (`web/ui`).

### Docs

- Align the Chinese and English quota manuals with credential terminology and `auth_index` guidance for duplicate file names (`docs/quota`).

### Chore

- Add localized copy for account details, quota lifecycles, diagnostics, and OAuth operations (`web/i18n`).

### Build

- Exclude nested `node_modules` directories from Docker build contexts to prevent workspace dependencies from contaminating image builds (`docker`).

## Upgrade Notes

- This is a prerelease. Stable Docker version tags and `latest` are not updated; use the explicit image or assets for `v1.12.0-beta1`.
- `/auth-files` and `/quota` redirect to `/accounts`. Existing browser links remain compatible, but external navigation, documentation, and automation should migrate to the new entry.
- Manager Server automatically applies additive SQLite migrations for quota observations, windows, lifecycles, snapshots, and identity indexes. Back up the database, WAL, SHM, and `data.key` together before upgrading.
- `usage_events` remains the raw source of truth and derived monitoring data remains recoverable. Do not manually delete a live SQLite WAL.
- Persisted quota history, account-window usage, and server inspection require Manager Server. Pure CPA Panel deployments hide unavailable features.
- Provider quotas are queried only after an explicit user refresh. Opening details, refreshing history, or processing cooldown state does not poll upstream quota endpoints.
- OAuth excluded-model and model-alias controls depend on CPA endpoint support and remain read-only or unavailable when unsupported.
- This beta contains broad Accounts workspace and storage changes. Validate existing credentials, quotas, and monitoring data in a non-production environment first.
