## Overview

v1.12.10 focuses on correctness and operator feedback in credential and quota management, improves multi-credential quota refresh behavior, fixes xAI weekly-usage and monthly billing-boundary semantics, and reduces legacy Codex identity-read cost on large histories.

## Highlights

### Features

- Credential Management now includes an `Enabled` status filter for credentials whose configured switch is on. `Enabled` remains distinct from `Available`, which also depends on current health and quota evidence. (Web)
- Quota refreshes for different credentials can now run concurrently while repeated refreshes for the same credential remain deduplicated. Codex reset-credit expiry entries also show remaining days. (Web)

### Fixes

- Credential operation notifications are now rendered above Drawer / Modal overlays. Single-credential quota refresh keeps exact provider errors, batch refreshes provide clearer summaries, and user-triggered model refreshes report their final success or warning state. (Web)
- Accounts now group standard, model-scoped, and other quota windows by semantic meaning. Billing / PAYG windows are no longer treated as standard interval quota, and top-level Codex and Kimi quota summaries select the correct windows again. (Web)
- Unknown-kind interval quota restored from snapshots keeps the same semantic grouping as live data. Model quota with incomplete boundaries remains visible without fabricated interval statistics or misleading missing-stat warnings. (Web)
- While a credential quota refresh is in progress, the static refresh glyph is hidden so only the loading indicator is shown. (Web)
- xAI weekly usage remains unknown when upstream omits `creditUsagePercent` instead of being synthesized as 0% used / 100% remaining. Explicit zero remains valid evidence, and weekly reset boundaries stay independent from monthly billing resets. (Web / Manager Server)
- Legacy Codex identity validation no longer materializes every matching historical event into Go. Manager Server reads compact derived identity evidence while preserving the existing fail-closed provider, member, workspace, marker, and chronology rules. (Manager Server)

## Upgrade Notes

- This release adds the rebuildable derived table `usage_codex_legacy_identity_evidence_v1` to accelerate legacy Codex identity validation. Historical evidence is populated in the background and resumes after restart; HTTP startup does not wait for the historical backfill to finish, raw `usage_events` are not rewritten, and no manual migration is required.
- When xAI omits weekly usage percentage evidence, the UI now keeps that value unknown instead of showing a derived 0%. This is a semantic-correctness change and does not mean the quota itself changed.
- `Enabled` only means the credential's configured enablement switch is on. `Available` continues to include current health and quota-evidence checks.
