## Overview

v1.12.10 聚焦凭证管理与配额展示的正确性和操作反馈，改善多凭证额度刷新体验，修正 xAI 周额度与月度账期边界，并优化大型 Codex 历史库的旧身份验证读取性能。

## Highlights

### Features

- Credential Management 新增 `Enabled` 状态筛选，可单独查看配置上处于启用状态的凭证；`Enabled` 与同时要求健康和额度证据的 `Available` 保持明确区分。（Web）
- 不同凭证的额度刷新现在可以并行执行，同一凭证的重复刷新仍会去重；Codex reset-credit 过期记录同时显示剩余天数。（Web）

### Fixes

- 凭证详情中的操作通知现在始终显示在 Drawer / Modal 之上；单凭证额度刷新保留具体 Provider 错误，批量刷新提供清晰汇总，用户主动刷新模型时也会得到最终成功或警告结果。（Web）
- Accounts 按标准额度、模型额度和其他额度的语义正确分组窗口；Billing / PAYG 不再被误当作标准区间额度，Codex 与 Kimi 的顶层额度摘要恢复正确选择。（Web）
- 从 snapshot 恢复的未知类型区间额度保持与实时数据一致的语义分组；边界不完整的模型额度仍可见，但不会伪造区间统计或显示不准确的缺失统计提示。（Web）
- 单凭证额度刷新进行中时不再同时显示静态刷新图标和 loading 图标。（Web）
- xAI 周额度未提供 `creditUsagePercent` 时保持“未知”，不再合成 0% 已用 / 100% 剩余；显式零值仍作为有效字段证据，同时周额度 reset 与月度 billing reset 保持独立。（Web / Manager Server）
- Codex 旧身份验证不再把大型历史中的每条匹配事件全部传入 Go；Manager Server 使用紧凑的派生 identity evidence 进行分组读取，同时保持现有 provider、member、workspace、marker 与 chronology 的 fail-closed 判定。（Manager Server）

## Upgrade Notes

- 本版本新增可重建的派生表 `usage_codex_legacy_identity_evidence_v1`，用于加速 Codex 旧身份验证。历史 evidence 会在后台补齐并可在重启后继续；服务启动不会等待历史补齐完成，原始 `usage_events` 不会被改写，无需手工迁移。
- xAI 上游省略周额度使用百分比时，界面现在会保持未知状态，而不是显示人为推导的 0%；这是数据语义修正，不代表额度发生变化。
- `Enabled` 只表示凭证配置开关已启用；`Available` 仍包含当前健康状态和额度证据判断。
