## Overview

这是 v1.12.0 的首个 beta 版本，重点交付统一凭证管理工作区、Provider 额度证据与账号级诊断。前端将凭证、额度、配置、模型、健康状态和请求活动集中到 `/accounts`，Manager Server 增加额度窗口生命周期持久化与身份隔离的监控读取，并在 CPA Panel 与 Full Docker 模式之间保持明确的能力边界。

## Highlights

### Features

- `/accounts` 成为统一凭证管理入口，旧 `/auth-files` 与 `/quota` 路径通过兼容跳转保留，并提供桌面、移动端、列表和卡片视图（`web/accounts`）。
- 凭证详情整合概览、额度、配置、模型、活动与诊断，可查看健康状态、最近请求、重新授权和恢复建议（`web/accounts`）。
- Provider 额度卡片支持完整周期、历史周期、模型范围、重置记录、精确观察时间、用量预测和周期对比（`web/quota`）。
- Provider 额度刷新改为显式手动操作，并与历史刷新分离；重复刷新按 Provider 串行执行，失败时保留已有额度（`web/quota`）。
- Manager Server 持久化额度观察、窗口、激活、周期和 allowlist snapshot，不保存 Provider 原始响应正文（`manager-server/quota`）。
- 账号历史和窗口用量按凭证身份、Provider 与精确时间范围查询，支持最近请求状态和凭证级钻取（`manager-server/monitoring`）。
- OAuth 排除模型和模型别名可在统一工作区预览和管理，多 Provider 别名变更支持失败回滚（`web/auth-files`）。
- 凭证配置工作区支持状态、代理、排除模型和 OAuth 规则的账号级呈现（`web/accounts`）。

### Fixes

- 使用文件名、`auth_index`、Provider 和来源组成的身份范围，避免同名凭证、无 Provider 记录和缓存之间发生错误归属（`web/identity`、`manager-server/identity`）。
- CPA 连接或 Manager 作用域变化时，在布局提交前清除旧额度、巡检结果和 OAuth 状态，并忽略旧请求返回的数据（`web/connection-scope`）。
- 多步骤凭证写入固定使用操作开始时捕获的 CPA 连接，旧连接的 401 或响应元数据不会影响当前会话（`web/api`）。
- Full Docker 与 CPA Panel 模式分别判断 Manager 存储、请求监控和服务端巡检能力，不再复用过期能力状态（`web/panel-mode`）。
- 统一 Provider 重置时间、周期边界和额度可用性语义，刷新失败或空窗口时不再误清除已有结果（`web/quota`）。
- 凭证编辑器和确认信息继续使用脱敏预览，避免展示原始认证内容（`web/auth-files`）。

### Performance

- 账号窗口用量优先使用覆盖完整的派生监控读取，并在边缘或尾部数据缺失时回退原始 `usage_events`（`manager-server/monitoring`）。
- 新增凭证窗口和最近请求索引，减少账号历史、窗口用量和最近状态查询的扫描范围（`manager-server/sqlite`）。

### Refactor

- 账号工作区复用详情抽屉、健康徽章、额度窗口卡片、相对时间和统一数据颜色，减少页面间展示差异（`web/ui`）。

### Docs

- 中英文额度手册统一使用凭证与账号身份术语，并说明按 `auth_index` 区分同名凭证（`docs/quota`）。

### Chore

- 为新的账号详情、额度生命周期、诊断和 OAuth 操作补充多语言文案（`web/i18n`）。

### Build

- Docker 构建上下文排除所有层级的 `node_modules`，避免工作区依赖污染镜像构建（`docker`）。

## Upgrade Notes

- 这是 prerelease。Docker 的稳定版本标签和 `latest` 不会更新，请显式使用 `v1.12.0-beta1` 对应镜像或资产。
- `/auth-files` 与 `/quota` 会跳转到 `/accounts`；已有浏览器链接仍可使用，但外部导航、文档和自动化建议迁移到新入口。
- Manager Server 会自动执行增量 SQLite 迁移，新增额度观察、窗口、生命周期、snapshot 和身份索引。升级前请同时备份数据库、WAL、SHM 与 `data.key`。
- `usage_events` 仍是原始事实来源，派生监控数据可恢复；不要手动删除运行中的 SQLite WAL。
- 持久化额度历史、账号窗口用量和服务端巡检依赖 Manager Server。纯 CPA Panel 模式会隐藏不可用功能。
- Provider 额度只在用户主动刷新时请求；打开详情、刷新历史或处理冷却状态不会自动轮询上游。
- OAuth 排除模型与模型别名能力取决于 CPA 端点支持；不支持时界面会保持只读或显示不可用状态。
- 此版本包含大范围账号工作区和存储变更，建议先在非生产环境验证现有凭证、额度与监控数据。
