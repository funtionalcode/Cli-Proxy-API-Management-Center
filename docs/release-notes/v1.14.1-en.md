## Overview

v1.14.1 is a stability patch for v1.14.0 that fixes Usage Maintenance failing to open in some reverse-proxy deployments.

The Manager Server natively returns `204 No Content` for `HEAD /v0/management/usage/maintenance`, but some reverse-proxy paths normalize that HEAD request to `200 OK`. The v1.14.0 frontend required an exact 204 response for capability detection, so a working maintenance endpoint could be incorrectly reported as `This Manager Server does not support usage maintenance.`.

v1.14.1 accepts either `200` or `204` for the capability probe while retaining the existing real GET response and schema validation that determines whether the maintenance API is actually supported. Legacy or incompatible Manager Server payloads therefore remain rejected.

## Highlights

### Fixes

- Fix Usage Maintenance being incorrectly reported as unsupported when a Docker / Nginx or other reverse-proxy deployment returns `200` for the HEAD capability probe. (Web)
- Preserve the existing GET payload schema validation, so a HEAD `200` does not make legacy or malformed maintenance responses appear supported. (Web)
- Add regression coverage for a proxied HEAD `200` while retaining the native `204` capability path. (Web / Tests)

## Upgrade Notes

- No database migration or configuration change is required.
- Users following the documented Nginx reverse-proxy deployment do not need to change proxy configuration for this fix.
- Usage Maintenance still requires the corresponding CPAMP Manager Server maintenance API.
- The full Muse / Meta compatibility baseline remains **CPA v7.3.4+**; this release does not raise the minimum CPA compatibility baseline.
