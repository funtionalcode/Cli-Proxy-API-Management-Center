## Overview

v1.14.0 is a feature release centered on the lifecycle of historical usage data. The new **Usage Maintenance** workspace brings archiving, verification, online-detail cleanup, import/export, resumable jobs, and storage diagnostics into one explicit workflow for long-running installations and growing SQLite databases.

The release also adds an offline space-reclamation path through `compact-usage`. It runs only after Manager Server is stopped and uses exclusive locking and integrity checks before compacting SQLite. Query, rollup, pricing-coverage, and recovery boundaries are hardened for installations that have already archived and removed raw historical usage, so logical cleanup, filesystem space reclamation, and full-history recovery remain distinct operations.

A separate correctness fix keeps provider display metadata out of routing configuration: upstream `display_name` / `displayName` values are no longer silently written as CPA routing aliases, preventing an imported friendly label from changing the externally callable model ID.

## Highlights

### Usage Maintenance

- Add a dedicated **Usage Maintenance** workspace with Archive Management and Import/Export as the primary surfaces, plus persisted task state, filters, detail drawers, and browser-history restoration. (Web / Manager Server)
- Preview historical data at a fixed cutoff and then progress through **archive → verify → separately confirmed online-detail cleanup**. Archiving and deletion remain distinct authorization stages. (Web / Manager Server)
- Persist archive stage and progress so long-running work can recover after page reloads, request cancellation, or service restarts without coupling background execution to one browser request. (Web / Manager Server)
- Add maintenance locks, coverage/readiness checks, and explicit stage transitions that prevent conflicting archive, verification, deletion, and compaction operations. (Manager Server)
- Add optional automatic historical retention. It is disabled by default and runs only after explicitly enabling the retention configuration. (Manager Server)

### Archive / Import / Export

- Store historical archive runs under `usage-archives/` as ordered gzip JSONL segments, with run, segment, identity-ledger, and verification state persisted in SQLite. (Manager Server)
- Export a stable JSONL snapshot of the current online `usage_events` independently of `USAGE_QUERY_LIMIT`; events written after the snapshot begins are not included. (Web / Manager Server)
- Add resumable import sessions with chunked upload, server-provided chunk sizes, temporary-file disk quotas, active-session limits, and TTL cleanup. (Web / Manager Server)
- Verify the SHA-256 of an already-uploaded prefix before resuming an import session, rejecting a different file even when filename, size, or modification metadata happen to match. (Web / Manager Server)
- Preserve an identity ledger so archived-and-cleaned raw events cannot be resurrected by duplicate import, while ordered archive segments can still rebuild raw history in an isolated empty recovery instance. (Manager Server)

### Historical Query And Data Safety

- Harden Request Monitoring, Usage Analytics, Dashboard, and pricing-coverage reads around historical cleanup. Derived data continues to serve supported long-window queries without pretending deleted raw events are still online. (Web / Manager Server)
- Permit raw deletion only after archive verification and aggregate/coverage readiness checks. A later statistics-refresh failure does not undo a successfully persisted archive stage. (Manager Server)
- After the first historical raw deletion, historical pricing-model membership and context-tier threshold structure enter a fail-closed protection boundary so deleted history cannot become structurally unrebuildable; rate-only changes remain allowed. (Manager Server)
- Full-history recovery depends on a consistent pre-cleanup backup. A normal JSONL export does not automatically merge already-deleted archive segments back into online raw usage. (Manager Server / Docs)

### Offline Compaction

- Add the native command `cpa-manager-plus compact-usage --db-path <usage.sqlite>`. (Manager Server / Native)
- Require every Manager Server using the database to be stopped. Process locking, SQLite exclusive access, maintenance locks, and active archive stages block unsafe compaction. (Manager Server)
- Emit stage/heartbeat status for long-running compaction work while keeping the final machine-readable `CompactResult` JSON on stdout. (Manager Server)
- Never run compaction automatically. It does not modify `data.key` or advance usage-data migration checkpoints; operators should conservatively reserve temporary free space up to roughly twice the SQLite file size. (Docs)

### Model Discovery Alias Fix

- Stop `normalizeModelList` from treating upstream `display_name` / `displayName` as the configured routing `alias`. (Web)
- Keep friendly display metadata visible and searchable in discovery and model catalog surfaces without changing the CPA-registered external model ID. (Web)
- Preserve explicitly supplied upstream aliases and user-configured aliases exactly as before. (Web)
- **Existing bad aliases are not rewritten automatically.** If an older import already saved a friendly display name into the alias field, clear it manually when canonical routing is desired. (Web)

## Upgrade Notes

- **No manual database migration is required.** Manager Server automatically creates or upgrades the additive Usage Maintenance schema at startup, and upgrading by itself does not delete historical `usage_events`.
- **Automatic retention is disabled by default.** Historical retention runs only when `USAGE_ARCHIVE_RETENTION_ENABLED=true` is explicitly configured.
- **Before any raw cleanup, keep one consistent backup set:** `usage.sqlite`, `usage.sqlite-wal`, `usage.sqlite-shm`, `data.key`, and `usage-archives/` must come from the same backup point.
- **`compact-usage` is offline-only.** Stop every Manager Server using the SQLite database before running it. Logical deletion does not shrink the SQLite file automatically.
- The complete Usage Maintenance JSONL export covers only raw `usage_events` still present when its snapshot starts. It does not merge already-deleted archive segments into the export and is not a complete CPAMP backup.
- After historical raw cleanup has been performed, downgrading is no longer equivalent to simply replacing the binary if complete historical semantics must be restored. Use the consistent pre-cleanup backup or a recovery path provided by the target version.
- The full Muse / Meta compatibility baseline remains **CPA v7.3.4+**; v1.14.0 does not raise the CPA minimum compatibility baseline.
