# CPA Manager Plus v1.13.0

> 30 commits since v1.12.14

> [中文 ->](https://github.com/seakee/CPA-Manager-Plus/blob/v1.13.0/docs/release-notes/v1.13.0-zh.md)

## Overview

v1.13.0 is a feature release focused on Devin provider support and upgrade reliability. CPAMP can now recognize Devin credentials and models, complete Devin authorization from the OAuth page, and display Daily / Weekly quota windows, reset times, and subscription-plan details in account views. Visual Config also adds editing for `devin.sensitive-words`, while related model, account, and monitoring presentation is integrated into the existing provider system.

Devin request execution and authentication remain CPA-owned. CPAMP only manages, presents, and calls the existing Management API. CPA v7.3.2 or later is required for the complete Devin OAuth callback flow.

This release also fixes remembered CPAMP Admin Key recovery after browser version or User-Agent changes, improves Native installer compatibility with legacy `<install_dir>/data` layouts and the historical `bash install-cpamp.sh update` invocation, and stabilizes missing-model-price attention by using a fixed icon footprint with explicit ownership by the primary cost card.

This release introduces no database schema migration, requires no offline maintenance, and adds no new required CPAMP configuration.

## Highlights

### Features

- Add Devin provider support across Accounts, OAuth, model recognition, Request Monitoring, and related provider presentation, including recognition of Devin credentials and `devin/*` models. (Web)
- Add the Devin OAuth flow through the CPA Management API, including authorization URL retrieval, remote callback URL submission, authorization-status polling, cancellation, and reauthentication. Responses from a previous connection are ignored after the active connection changes. (Web / CPA)
- Add Devin Daily / Weekly quota windows, reset times, and subscription-plan details, integrated with the standard account quota snapshot and historical-window pipeline. (Web / Manager Server)
- Add Visual Config editing for `devin.sensitive-words`. Values are normalized on save while unknown sibling configuration is preserved, and clearing the setting removes only an otherwise-empty Devin subtree. (Web)

### Fixes

- Integrate Devin quota and plan information into the standard account quota snapshot and account-detail paths instead of maintaining a separate presentation path, avoiding duplicate cards and divergent state. (Web / Manager Server)
- Fix remembered CPAMP Admin Keys becoming unreadable after the browser User-Agent changes. The new local obfuscation format is scoped to the site environment, legacy values migrate only after successful server authentication, transient network failures / 403 / 5xx responses preserve legacy credentials, and a definitive 401 still clears invalid credentials. (Web)
- Fix Native upgrades failing to locate historical data when older installations stored it under `<install_dir>/data`. The fallback is enabled only when there is no explicit data-path authority and no current runtime database is present; existing data is not moved, copied, or symlinked. (Installer)
- Restore support for the historical positional `bash install-cpamp.sh update` invocation and keep it equivalent to `CPAMP_OPERATION=upgrade`; conflicting or unknown arguments fail closed. (Installer)
- Stabilize missing-model-price attention with a fixed-size icon instead of localized inline text, and ensure shared Usage Analytics summaries display the indicator only on the designated primary cost card. (Web)
- Fix Release dry-run authorization when GitHub Actions uses a dynamic run name. (Release tooling)

## Upgrade Notes

- **No database schema migration or offline maintenance is required.** Existing CPAMP data structures and deployment modes remain compatible.
- **CPA v7.3.2 or later is recommended as the minimum version.** The complete Devin OAuth callback fix is available from CPA v7.3.2; upgrade CPA first when using Devin. Existing management behavior for other providers is unchanged.
- Legacy remembered Admin Keys stay in the old format until they have successfully authenticated against the server; transient network failures do not trigger destructive migration or cleanup.
- Native upgrades continue to honor explicit configuration and launcher arguments. The legacy `<install_dir>/data` fallback is used only when the current dataset cannot be resolved and a complete historical dataset is detected.
- Devin request execution, OAuth authentication, and upstream protocol handling remain owned by CPA; CPAMP does not implement a separate Devin request transport layer.
